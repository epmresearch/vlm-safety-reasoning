## 5. Facts the plan must respect

1. **Boxes are `[0,1]` everywhere in ground truth.** `build_target_json` scales to `[0,1000]`
   itself for the SFT target. Rescaling again collapses every box to a point and silently
   zeroes every IoU (CLAUDE.md, "Rewards and the output contract").
2. **MOCS rows must never be written into `datasets/augmented`.** `unified` reads that
   directory too, and MOCS has 13 categories of its own — none of them
   `excavator`/`rebar`/`worker_with_white_hard_hat` — so empty means *unannotated*, not
   *absent*, and would teach `unified` those objects are missing on thousands of images. The
   new-directory approach exists to avoid this; do not shortcut it.
3. **The `test` split of `augmented_v3` must hold the same `image_id` set as
   `datasets/augmented`'s test split.** `run_inference.py` loads the *default* root for every
   task, so comparability with v2 is automatic *only* if no MOCS row leaks into test.
4. **The image column must be named `image`, singular** (invariant 1 — TRL looks for exactly
   that key).
5. **`grpo_pool_v3` must stay ~50/50 violation/safe.** `p* = 0.298` is solved against that
   ratio; change it and the operating point moves silently. Re-run
   `scripts/validate_rewards.py --task violations_think --probe --pool-stats`.
6. **`thinking` is inner text only, no `<think>` tags**, exactly five lines, caption then
   `rule_1 → rule_4`, all four lines on every image including safe ones, no coordinates.
   Import `build_think_body`; do not re-implement.
7. **A contradictory `thinking` row** (verdict disagreeing with the row's own labels) trains
   the model to invert evidence and nothing downstream can detect it. That is what
   `think_row_problems` and `validate_think_dataset.py` exist to catch.
8. **Re-running `--version v2` destroys the existing v2 results** — `run_inference_batched`

9. **Never run the full test suite on ARC** — one test shells out to a real `sbatch` and
